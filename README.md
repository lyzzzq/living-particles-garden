# 生长

全屏手势花园课程期末项目，使用 HTML、CSS、JavaScript、p5.js 与 ml5.js Hand Pose。

## 启动

在 VS Code 打开本仓库，右键 index.html，选择 Open with Live Server。在 localhost 页面点击「开启手势」，允许摄像头访问。依赖与识别模型需要联网加载。

## 操作

- 指尖在同一位置停留一秒：种下一朵随机大小、花型的花。移动到新位置可再次种植。
- 移动：短暂粒子反馈，以及有疏密变化的短草、藤蔓和多色碎花群。
- 张掌：附近花朵绽放；握拳：附近花朵闭合。
- 鼠标也可练习；空格模拟张掌，F 模拟握拳。
- 「收藏画作」保存 PNG，排除蝴蝶光标与界面。

## 文件与检查

index.html 是页面，style.css 是全屏样式，sketch.js 是绘制与手势逻辑。详细说明见 [使用说明](使用说明.md)。已提供两张离屏预览，它们不是浏览器实拍截图。

安装 Node.js 后运行 npm test，检查停留触发、随机大小、草花藤变化、连接、反馈消退和模型就绪流程。测试使用模拟输入；真实摄像头速度和浏览器视觉仍需实测。

## 过程保存

[HISTORY.md](HISTORY.md) 记录可恢复的三个阶段，每个阶段对应独立 Git commit 和标签。它们是从现存备份补录，日期为本次归档日期，早期缺失步骤无法完整还原。代码在 AI 协作中完成，应按课程要求说明协作方式。

以后每完成一个明确步骤，应在测试后保存一次 commit，并 push 到 GitHub。仅在网页上上传最终三个文件，不能保留本仓库的完整提交历史；应推送整个 Git 仓库。

## GitHub Pages 部署

推送包含历史的 main 分支和阶段标签后，在 Settings → Pages 中选择 GitHub Actions，再在 Actions 中运行 Test and deploy garden。成功后 github-pages 环境会显示网址。后续推送 main 会先检查再自动部署。

流程依据：[GitHub Pages 官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。

## 空灵花园音效

点击「开启声音」后播放。默认音量 30%，可调音量或再次点击关闭。背景是很轻的合成风声与缓慢起伏的和声；移动速度改变沙沙声，停留一秒种花时出现清透铃音，大花使用稍丰富的音符层次。张掌产生上行铃音、背景音色渐亮，握拳产生下行音符、音色渐暗。切换到其他标签页会暂停声音，回来后可点击重新开启。

声音使用 Web Audio API 实时合成，不使用歌曲、麦克风或外部音频素材。只有成功种下的新花会发声，初始底景不自动敲铃；手势音效有间隔和数量上限，避免识别抖动造成声音堆叠。浏览器会要求用户主动点击后才能播放声音，参考 [Web Audio 最佳实践](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices)。

模拟检查覆盖首次点击启动、移动反馈、失去输入后恢复轻风、种花铃音、手势音效间隔、最大叠音、节点释放、音量与静音、页面隐藏暂停。实际听感仍需在浏览器试听。

## 持续创作与渐隐换景

修复旧版达到数量上限后停止生长、种花失败后不再重试的问题。停留一秒仍只在同一位置成功种一次花；换位置可继续。位置拥挤、种植失败时会重新计时尝试，逐步让较早植物退场，避免误显示已播种。

以有效移动生长和播种尝试为步骤记录：较早枝影约 60 步后开始淡出，花朵保留得更久；画面提前拥挤时也会先淡化较早元素。渐隐持续约四秒，结束后移除对应纹理引用并释放位置。停止创作时不继续按时清空整幅作品，累计播种数仍保留。

可见活动植物数量根据屏幕空间控制，旧元素渐隐期间新元素已可生长。长时模拟检查覆盖 260 个生长步骤、后半程继续种花、数量受控、渐隐清理以及原地失败重试。

背景和声略微提高，并加入每 8–12 秒一组、音量很轻的慢速旋律。开启声音后才播放，仍可调音量或静音。
